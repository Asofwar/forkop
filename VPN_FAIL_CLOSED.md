# Селективная защита VPN

Настройка `forkop.settings.vpn_fail_closed=1` добавляет независимую таблицу
`inet ForkopVpnGuard` и службу `/etc/init.d/forkop-guard`. Защищаются включённые
разделы connection/vpn/proxy/outbound. Zapret, Zapret2, ByeDPI и bypass сохраняют
свой приоритет и исключаются из защиты.

Для включения требуется **dnsmasq-full с поддержкой nftset**. Обычный dnsmasq
не подходит: проверка отклонит конфигурацию до применения. Пакет не заменяется
автоматически при переключении опции; на проверенном роутере установлен
dnsmasq-full той же версии 2.93-r1 с сохранением DHCP-конфигурации.

## Поведение

- Работающий Форкоп обслуживает трафик как раньше. Интерфейсные VPN-outbound
  получают отдельную метку; nftables запрещает выход с этой меткой через другой
  интерфейс. Селекторы с прямым WAN-fallback отклоняются.
- После остановки Форкоп правила остаются в ядре. Защищённые статические
  подсети/порты отклоняются; кэшированные FakeIP не выходят в forwarding.
- Независимые процессы dnsmasq отвечают NXDOMAIN для защищённых доменов при
  остановке sing-box. Остальные домены используют исходные upstream dnsmasq и
  обычный OpenWrt resolv-файл. Источники и приоритет исключений учитываются.
- DNS-ответы явных DPI/bypass-исключений заполняют отдельные IPv4/IPv6 nftset
  для каждого профиля источников. Эти адреса разрешаются перед VPN-подсетями:
  например, YouTube остаётся разрешён даже при пересечении с VPN-подсетью Google.
  Записи живут не более суток. Firewall reload сохраняет оставшееся время жизни.
  Перед штатным shutdown/reboot служба сохраняет `exceptions.json`, при старте
  восстанавливает только неистёкшие записи с совпадающей DNS-политикой.
- Снимок политики сохраняется атомарно в
  `/etc/forkop/vpn-guard/policy.json`; DNS-конфигурации восстанавливаются из него
  в `/tmp`. Снимок включён в sysupgrade backup.
- Init, firewall include и interface hotplug восстанавливают таблицу. Независимый
  watcher раз в секунду сверяет PID/starttime sing-box через ubus. Переключение
  на рабочий DNS требует проверки принадлежащего Форкоп процесса, портов и
  сетевого runtime. При переключении очищается только conntrack TCP/UDP DNS
  на порту 53, чтобы старый DNAT не направлял запросы на остановленный процесс.
- Штатный stop Форкоп удерживает offline DNS до его успешного запуска: watcher
  не может снять защиту между восстановлением обычного DHCP/DNS и остановкой
  sing-box. При неожиданной остановке sing-box применяется автоматический
  offline; после восстановления watcher повторяет проверку готовности.
- Flow offload отключается при включении: он обходит forward hooks. Предыдущие
  значения сохраняются и восстанавливаются при явном снятии защиты.

Домен и IP в обычном правиле sing-box объединяются через ИЛИ; logical AND
разбирается отдельно. Для DNS поддерживаются exact/suffix, локальные JSON/SRS
списки, до четырёх независимых групп источников и source exclusions. Regex,
keyword и домены с дополнительными условиями портов/протокола отклоняются до
публикации конфигурации, а не молча упрощаются.

## Включение и снятие

На OpenWrt, Linux shell:

```sh
ucode -L /usr/lib/forkop /usr/lib/forkop/nft/fail_closed.uc check-live
uci set forkop.settings.vpn_fail_closed='1'
uci commit forkop
/etc/init.d/forkop reload
```

Отключение опции само по себе не удаляет сохранённую защиту. Для явного снятия:

```sh
uci set forkop.settings.vpn_fail_closed='0'
uci commit forkop
/etc/init.d/forkop-guard release
/etc/init.d/forkop reload
```

Полное удаление через штатный full-uninstall сначала снимает защиту.
Прямое удаление пакетов вручную требует предварительного `release`, иначе
firewall include потеряет исполняемый файл после удаления пакета.

## Границы гарантии

Доменные правила относятся к клиентам, использующим DNS роутера/перехваченный
TCP/UDP DNS. Произвольный DoH/DoT, внешний VPN и заранее полученные реальные IP
доменных сервисов не позволяют ядру восстановить доменное имя после остановки
sing-box. Такой обход не покрывается доменным kill-switch; статические IP и
метки защищаются независимо от DNS. Это не блокировка всего интернета.

Исключение по IP действует для всего адреса в соответствующем профиле: ядро
не различает VPN-домен и DPI-домен на одном общем CDN-IP. Без анализа имени
в каждом соединении одновременно гарантировать абсолютную доменную блокировку
и свободный прямой доступ DPI на общем IP нельзя. При аварийном отключении
питания последние IP-исключения могут быть потеряны: для DPI требуется свежий
DNS-запрос. При изменении списков прежние исключения сбрасываются.

При полном stop Форкоп также останавливает управляемый им Zapret: новая защита
не запрещает его реальные назначения, но не поддерживает остановленный DPI
процесс. Старые FakeIP DPI требуют нового DNS-запроса/истечения клиентского
кэша. IPv6 обрабатывается теми же правилами; внешние туннели не вскрываются.

После удаления и пересоздания интерфейса awg1 на проверенном роутере наблюдались
таймауты обычного DNS в продолжающем работать sing-box. Перезапуск sing-box
восстановил ответы. Guard проверяет принадлежность процесса и сетевой runtime,
но не проверяет доступность каждого upstream DNS/VPN-сервера; его состояние
online означает возвращение DNS в управляемый путь, а не проверку внешней связи.

## Проверки

Из PowerShell на Windows:

```powershell
rtk proxy wsl -e bash /mnt/e/Projects/forkop/tests/vpn_fail_closed.sh
rtk proxy wsl -u root -e bash /mnt/e/Projects/forkop/tests/router/vpn_guard_packets.sh
```

Первый тест использует настоящий ucode-компилятор, второй — настоящие сетевые
namespace и nftables. Они не меняют Windows или production-сеть роутера.
Аппаратную проверку следует фиксировать отдельно от этих локальных результатов.
