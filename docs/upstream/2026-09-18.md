## Selected: Discord routing over shared Cloudflare ranges

The Discord community subnet list also carries shared Cloudflare Anycast CIDRs.
Routed as ordinary Discord networks they capture unrelated sites and P2P.

This fork was fully exposed, and in a way that reads as handled:
`nft_add_community_subnet_file_for_section()` accepted `service`, `discord_set`,
`discord6_set`, `interface_set` and `mark` and then ignored all of them,
forwarding straight to the generic `nft_add_subnet_file_for_section()`. The
parameters are leftovers from an earlier implementation; the special handling
was gone, so every Discord CIDR including the shared Cloudflare ones landed in
the plain destination subnet sets.

The port gives each section `udp_ip_ports` / `udp_ip6_ports` sets, emits the
matching rule pair only when the section actually enables the Discord list, and
splits the list on load: shared ranges go to the UDP sets scoped to Discord's
media ports, dedicated ranges keep the ordinary path including the section port
filter. Only the Discord list is split — the dedicated Cloudflare list and every
other service are untouched.

The advisory warning for Discord and Cloudflare enabled together is ported as a
plain log line rather than upstream's `[routing-warning]` prefix, which belongs
to their UI notification pipeline.

`tests/discord_cloudflare_split.sh` covers the CIDR classification, the media
port set, the split contract and the Discord-only gating.

## Deferred: mixed rule-set kind for sing-box 1.14 DNS

Upstream marks community rule-sets that carry address matchers as a new `mixed`
kind, so sing-box 1.14 evaluates them against a DNS response instead of using
them as legacy query filters. It adds `community_kind()`, `has_ip_matchers()`,
and reworks the generator's DNS rule construction to split query and response
tags.

Not imported yet. This fork consumes `kind` through eight `kind == "domains"`
comparisons in `singbox/generator.uc`; introducing a third value without
reworking every one of them would silently drop community lists out of the DNS
rules — the opposite of the intended fix, and on the feature that matters most.

It is also dormant here: the split is gated on
`runtime_supports_dns_response_matching`, which is false below sing-box 1.14,
and the routers on this fork run sing-box-tiny 1.13.21 from the OpenWrt 25.12
feed. It becomes live when sing-box 1.14 reaches the feeds.

Port it as its own change, with tests for a domain-only list, an
address-only list and a mixed list, on both 1.13 and 1.14 code paths.
