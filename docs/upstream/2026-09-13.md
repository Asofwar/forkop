# Selective upstream audit: 2026-09-13 (evening)

This is a selective source port, not a merge. Test results and publication

## Selected changes

### Package upgrade no longer leaves Forkop stopped (opkg)

`prerm` decided whether to record "restart me afterwards" from its action
argument. opkg passes no action on some OpenWrt 24 builds, including an
ordinary version upgrade, so the marker was erased and `postinst` did not
restart a service that `prerm` had just stopped.

The fork's ipk `prerm` forwards `ARGV[0] || ""`, so it was affected; the apk
path passes `upgrade` and `remove` explicitly and was not. Since the mirror
publishes ipk for 24.10.0/24.10.1/24.10.5 and apk only for 25.12.5, this
covered most supported combinations.

The adaptation is narrower than upstream's. An explicit `remove` still erases
the marker, so removal semantics stay exact; only an upgrade or an absent
action falls back to the authoritative service state. Upstream treats service
state as authoritative for every action, which also writes a marker during a
genuine removal.

### Ownership gates before destructive transitions

`stop_main()` removes the nftables policy before the controlled sing-box stop
would reject ambiguous ownership. A stop could therefore discard the
fail-closed policy while an unknown sing-box stayed alive. This is the exact
gap recorded in the 2026-09-12 audit as a reason to defer the upstream
watchdog; it is now closed at the source instead.

`reload()` checked ownership only when the runtime already looked incomplete.
The check now precedes reload-state capture and candidate nft staging, so a
reload cannot rebuild the live dataplane before a later sing-box transition
notices that procd ownership is unsettled. `restart()` already had its gate.

procd can briefly report an old PID while replacing its child. That unsettled
observation is deliberately treated like a foreign process: preserve the
working dataplane and let the serialized caller retry after convergence.

### Support report memory

The report no longer runs a full `sing-box check`. That parses every outbound
eagerly and can briefly exceed the running runtime's memory on a 256 MiB
router, purely to collect diagnostics. The raw configuration is still included.

## Deferred changes and reasons

### Package upgrade quiesce

Upstream adds a `package-upgrade.quiesce` marker holding the prerm PID, a
`acquire-runtime-dir-lock-wait-until-package-upgrade` helper, and yields in the
latency worker. The goal is sound, but note that 1.3.16 shipped it broken:
`run_pending_reload_if_requested()` called `package_upgrade_quiescing()`
declared below it, which ucode compiles as a global load that the later
declaration never satisfies. Every call raised "left-hand side is not a
function" until 1.3.17 reordered the helpers. This fork independently found and
fixed the same class of defect in 1.0.16 and now guards it with
`tests/ucode_forward_reference.sh`.

The ownership gates above already close the dangerous window this fork had.
Import the quiesce marker only with tests covering a stale marker, a dead prerm
PID, and a worker that starts between `prerm` and `postinst`.

### Staged configuration validation and the config-error marker

Upstream moves the eager `sing-box check` out of generation and into the
lifecycle after the old runtime is stopped, then surfaces the failure through a
`config-error` file into the UI. The memory argument is real and the user-facing
error is an improvement.

It is deferred because it rewrites the fork's guarded transition: a rejected
stage calls `cleanup_failed_runtime()` unconditionally, which in this fork runs
`stop_main()` and the fail-closed policy decisions above. Adapting it needs
tests for a rejected stage with a live old runtime, a rejected stage after the
transition guard is already armed, and rollback failure.

### Latency reload handoff rework

Upstream replaces the synchronous pending-reload handoff with a request to
init.d plus `consume_pending_reload()` inside `reload_begin_value()`. This
addresses the batch-handoff race recorded on 2026-09-12.

This fork's handoff already differs: it retains the durable request and yields
when the marker survives. Adopting upstream's split changes marker ownership
between the worker and init.d, so it needs deterministic tests for handoff,
queued reload, and a worker that starts during the reload before it is worth
taking.

### Permanent start failure

Treating validation and generator rejections as permanent, and clearing the
failure marker only after a verified successful start, is reasonable. It
interacts with this fork's WAN-up retry and its startup-recovery logging added
in 1.0.16, so it needs its own retry-suppression tests first.

## Preserved invariants

- Any otherwise valid HTTPS subscription provider remains supported; no upstream
  provider allowlist or automatic node-exclusion default is imported.
- Release ownership remains `slayer326/forkop`; `fold8.ru/forkop` distribution and
  `mirror.infotechtg.ru` dependencies are not replaced by upstream endpoints.
- Preserve exact managed PID/start-time transitions, last-working subscription
  and list generations, transaction rollback and fail-closed ambiguity handling.
- No production-router installation is authorized by this source audit. Hardware
  validation, when absent, must be disclosed.
